# 姿势 × 服饰 × 人物生图

把动作、穿搭与人物身份分开控制，交付一张融合后的完整人物图。输入可以是用户附图、本地图片、可访问的图片链接，或明确的文字描述。此技能的产物是人物图；不包含社交发布、修改网站或部署。

## 确定三种输入

| 输入 | 用途           | 应保留／采用                                                 | 不应随之迁移                           |
| ---- | -------------- | ------------------------------------------------------------ | -------------------------------------- |
| 人物 | 身份与画风基准 | 五官、脸型、发型发色、肤色、体型比例及人物画风，遵循用户要求 | 原衣服与原姿势，除非要求保留           |
| 姿势 | 动作与观察角度 | 四肢位置、躯干转向、重心、支撑点、视角与合理遮挡             | 人偶线条、关节球、无脸头部或参考图体型 |
| 服饰 | 穿搭设计       | 版型、颜色、层次、材质、图案、配饰及鞋袜                     | 服装模特的脸、发型、体型和站姿         |

- 已有可用输入就继续，不为格式完整而要求用户重复提供。
- 某项可用文字表达；人物只有文字时按描述创造人物，不声称锁定了一个已有身份。
- 人物身份不明确，或缺少用户认为必须匹配的姿势／服饰参考时，简短请求补充，先整理其余参考。
- 用户明确授权自由设计某项时自行选择，不额外确认。
- 用户给的是参考库编号、链接或关键词时，按 [references/gallery.md](references/gallery.md) 获取对应素材；直接提供三张图时跳过参考库。

## 准备参考

1. 逐张查看图片并标注用途，不根据文件顺序猜“哪张是人物”。用户已标注的角色优先。
2. 选取清晰的原图作为实际生图输入；参考库缩略图用于选图，整页截图中的导航、按钮和文字不进入成图。如只提供 UI 截图，优先解析原参考编号；必要时裁出对应参考区域并保留原文件。
3. 默认一张结果、一位人物，尽量完整展示指定动作与服装，保留人物原有画风。构图、背景、尺寸或风格已有要求时照做；否则采用简洁背景和适合该动作的画幅。
4. 固定记录实际提交顺序与每张图的角色。可用“人物 → 姿势 → 服饰”，但以当前生成工具实际收到的顺序为准；不能在提示词里引用不存在的图号。

## 编写融合提示词

使用 [references/prompt-template.md](references/prompt-template.md) 组织提示词，保留用户的明确细节。要点：

- 人物图决定身份与画风，姿势图决定动作，服饰图决定穿搭。
- 衣服要随动作自然形变，透视、褶皱、遮挡与支撑关系一致。
- 输出单幅人物成图，不是参考拼贴、分屏、对照图或提示词卡片。
- 不添加第二个人、文字、水印、模型人偶线条或额外服装，除非用户要求。
- 参考有冲突时按上述职责分工解决；涉及用户明确要求之间的实质冲突才澄清。

## 执行生成

- 先告知本次融合的三项输入和生成方式，再实际生成。用户要求生成时，不能只交付提示词。
- 使用当前可用的生图能力，并遵守该工具及 `$imagegen` 的当前指引。默认使用内置图像工具；本地参考需先查看，使其进入上下文。
- 用户明确选择兼容 API、Atomflow 或具体模型时遵循该选择。兼容 API 模式默认 `gpt-image-2`，Atomflow 的服务预设为 `https://atomflow.vip/v1`；不要切换到 Grok 或其他模型。
- 需要 CLI/API 时，按已安装 `$imagegen` 的文档调用其多图编辑 CLI，使用重复的 `--image` 参数和清楚的图号职责，不另写临时 SDK runner。通过受信任的本地配置或环境变量提供凭证；不要把密钥写入技能、提示词、命令参数、截图或分享包。
- 人物为图片时实际提交三类参考；人物仅文字时提交姿势和服饰两张图，人物信息写入提示词。原图以工具要求的文件输入／multipart 上传，不把本地路径文本冒充已上传图片。
- 不从其他应用或浏览器存储中擅自提取密钥。不具备所选服务的连接或凭证时，明确缺少什么；不偷偷换服务。
- 默认仅生成一张。失败时保留参考和提示词，说明失败；不自动重复付费请求或默默更换模型。

## 检查与交付

查看实际结果，检查人物五官与发型、姿势支撑与关节、服装细节和穿着遮挡，确认没有把人物变成人偶或做成拼贴。明显偏差须如实说明；修正优先调整单项约束，不重写全部设计或反复自动生成。

保存结果到用户指定位置；未指定时放在本次工作区 `output/imagegen/`，使用新文件名避免覆盖。最终嵌入人物图并给出绝对文件路径；简述采用的参考、实际生成方式与可见偏差。只有提示词或未完成的请求不能称为“图片已生成”。

## 调用示例

- “用 $pose-costume-character，图一是人物，图二是姿势，图三是服饰，生成一张全身人物图。”
- “用 $pose-costume-character，人物用我上传的照片，姿势选 P047，服饰选 SPR-0050，保留人物脸和发型。”
- “用 $pose-costume-character，人物是黑色短发的成年女性，侧坐单臂上举，穿米色开衫和白色长裤，生成一张插画。”
